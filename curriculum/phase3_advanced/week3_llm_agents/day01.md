# Day 1: LLM 기초 — GPT, Claude의 작동 원리와 신약개발 활용

> 이전 학습에서 바이오의약품의 네 모달리티(항체·RNA·세포·유전자편집)와 각 모달리티에 특화된 "좁은" 예측 모델을 다뤘습니다(Week 2, Day 50). 오늘부터 시작하는 Week 3에서는 방대한 지식을 사전학습한 **대형 언어 모델(Large Language Model, LLM)**과 이를 도구로 부리는 AI 에이전트로 넘어갑니다. 오늘은 그 출발점으로, LLM이 무엇이고 어떻게 작동하며 신약개발에서 어디에 쓰이는지를 학습합니다.

## 개요

**대형 언어 모델(LLM)**은 인터넷 규모의 텍스트로 사전학습(pre-training)하여 "다음 토큰을 예측"하는 능력을 갖춘 초거대 신경망입니다. GPT, Claude, Gemini가 대표적이며, 신약개발에서는 논문·특허·실험 프로토콜을 읽고 요약·추론하는 지식 작업의 자동화 도구로 쓰입니다. 지금까지 배운 QSAR·GNN 같은 모델이 "분자 하나의 물성을 좁게 예측"했다면, LLM은 **비정형 텍스트에 잠겨 있는 도메인 지식 전체를 다루는 범용 추론 엔진**이라는 점에서 근본적으로 다릅니다. 약사-창업자에게 LLM이 중요한 이유는, 신약개발 지식노동(문헌 리뷰, 규제 문서 작성, 데이터 정제)의 상당 부분이 텍스트 처리이고 이것이 곧 자동화·제품화의 대상이기 때문입니다.

## 핵심 개념

### 1) 토큰과 다음 토큰 예측

LLM의 학습 목표는 단순합니다. 텍스트를 **토큰(token)**(단어보다 작은 조각, 예: "acetyl", "##ation")으로 쪼갠 뒤, 앞선 토큰들을 보고 **다음 토큰의 확률분포**를 맞히는 것입니다. 수십억~수조 개 토큰으로 이 예측을 반복하면, 모델의 가중치 안에 문법·사실·추론 패턴이 압축되어 저장됩니다. 이는 약학에서 익숙한 개념으로 대응됩니다 — 회귀모델이 잔차를 최소화하듯, LLM은 예측 확률과 실제 토큰 간의 **교차 엔트로피 손실(cross-entropy loss)**을 최소화하도록 최적화됩니다(Day 4에서 다룬 손실함수·최적화의 대규모 판본).

### 2) 트랜스포머와 어텐션

LLM의 뼈대는 **트랜스포머(Transformer)** 구조이며, 핵심은 **셀프 어텐션(self-attention)**입니다. 어텐션은 문장 안 각 토큰이 "다른 어떤 토큰에 주목해야 하는가"를 학습된 가중치로 계산합니다. 이 메커니즘은 우리가 Phase 2에서 본 분자 물성 예측용 트랜스포머(예: 분자 SMILES를 처리하는 모델)와 **동일한 수학적 기반**을 공유합니다. 즉 "서열 안의 원거리 의존성을 포착한다"는 성질은, 문장에서 대명사가 앞의 명사를 가리키는 것을 잡아내는 것과, 단백질 서열에서 멀리 떨어진 두 잔기(residue)의 상호작용을 잡아내는 것에 똑같이 작동합니다.

### 3) 사전학습 → 정렬(Alignment) → 추론

LLM은 세 단계를 거칩니다.

| 단계 | 하는 일 | 약학적 대응 비유(구조적 대응) |
|------|---------|------------------------------|
| **사전학습** | 대규모 텍스트로 다음 토큰 예측 | 광범위 스크리닝 라이브러리 학습 |
| **정렬(RLHF/RLAIF)** | 인간·AI 피드백으로 유용·안전하게 미세조정 | 리드 최적화 — 원하는 프로파일로 다듬기 |
| **추론(inference)** | 프롬프트를 받아 답을 생성 | 실사용(투여) 단계 |

Claude는 정렬 단계에서 **헌법적 AI(Constitutional AI)** — 명시된 원칙에 따라 모델이 스스로 응답을 비평·개선하는 방식 — 을 사용하는 것으로 알려져 있습니다. 이는 규제 산업에서 "왜 이렇게 답했는가"의 근거를 요구하는 신약개발 맥락과 궁합이 좋습니다.

### 4) 환각(Hallucination)과 그 통제

LLM은 확률적으로 그럴듯한 토큰을 생성하므로, 사실이 아닌 내용을 자신 있게 만들어내는 **환각(hallucination)**이 구조적으로 존재합니다. 신약개발처럼 정확성이 생명인 도메인에서는 이 한계가 치명적일 수 있어, 뒤에서 배울 **검색 증강 생성(RAG, Day 4)**과 도구 사용(Day 3)으로 근거를 강제하는 설계가 필수입니다.

## 작동 원리와 아키텍처

LLM을 제품에 붙일 때 필요한 것은 내부 수식이 아니라 **입력→처리→출력의 흐름**과 제어 가능한 파라미터입니다.

```
[LLM 애플리케이션 기본 구조]
1. 입력: 시스템 프롬프트(역할·규칙) + 사용자 프롬프트(작업) + 컨텍스트(문서)
2. 토크나이저: 텍스트 → 토큰 시퀀스
3. 트랜스포머: N-layer 어텐션 → 다음 토큰 확률분포
4. 디코딩: temperature/top-p로 토큰 샘플링 → 응답 생성
5. 출력: 텍스트(+구조화 JSON, 도구 호출 신호)
```

바이브코딩으로 LLM 도구를 만들 때 반드시 이해해야 할 설계 결정을 표로 정리합니다.

| 설계 결정 | 선택지 | 신약개발 맥락의 추천 | 이유 |
|-----------|--------|---------------------|------|
| temperature | 0 ~ 1.0+ | 사실 추출은 0에 가깝게 | 재현성·정확성 우선, 환각 억제 |
| 컨텍스트 창 | 수천~수십만 토큰 | 긴 논문·규제 문서는 대용량 창 | 문서 통째로 근거 제공 |
| 출력 형식 | 자유 텍스트 / JSON 스키마 | 파이프라인은 구조화 출력 | 다운스트림 자동 처리 |
| 근거 강제 | 순수 생성 / RAG·도구 | 규제·임상은 RAG 필수 | 출처 추적, 환각 방지 |

> 핵심: **컨텍스트 창(context window)**은 모델이 한 번에 "읽고 기억할 수 있는" 토큰의 최대 길이입니다. 이것이 클수록 임상시험 보고서나 특허 전문을 잘라내지 않고 통째로 넣어 근거 기반 응답을 받을 수 있습니다.

## 신약개발 적용

LLM은 이미 신약개발의 지식노동 계층에 상업적으로 침투했습니다. 구체적 사례로 살펴봅니다.

- **문헌·특허 자동 리뷰**: 수천 편의 논문에서 특정 표적(target)에 대한 근거를 추출·요약하는 작업은 전통적으로 수주가 걸렸으나, LLM 기반 도구로 크게 단축됩니다. **BenevolentAI**는 지식그래프와 결합한 문헌 마이닝으로 2020년 초 baricitinib을 COVID-19 후보로 재창출(repurposing) 제안한 사례가 잘 알려져 있습니다(이후 실제 임상에서 활용).
- **분자 특화 언어모델**: **MegaMolBART, MolFormer(IBM)** 등은 SMILES를 "언어"로 사전학습해 물성 예측·생성에 활용합니다. 이는 Day 2에서 자세히 다룰 화학 Foundation Model의 전조입니다.
- **의료·바이오 특화 LLM**: 구글의 **Med-PaLM 2**가 미국 의사면허시험(USMLE) 스타일 문항에서 전문가 근접 수준을 보고한 사례(2023, 정확한 수치는 확인 필요)는, LLM이 고도 전문 지식 작업에 도달했음을 보여줍니다.

기존 방법과의 비교는 아래와 같습니다.

| 작업 | 전통 방식 | LLM 활용 | 실무적 개선 |
|------|-----------|----------|-------------|
| 표적 문헌 리뷰 | 연구자 수동 검색·정독 | LLM 요약 + 근거 링크 | 시간 대폭 단축, 초안 자동화 |
| 실험 프로토콜 정리 | 수기 표준화 | 구조화 추출(JSON) | 데이터베이스 적재 자동화 |
| 규제 문서 초안 | 전문 인력 작성 | LLM 초안 → 전문가 검수 | 초안 비용 절감, 인력은 검증에 집중 |

> 유의: LLM 출력은 **초안·후보**이지 결론이 아닙니다. 특히 예측된 분자 속성이나 임상적 판단에 대해 LLM의 진술을 확실성으로 받아들여선 안 되며, 반드시 출처와 전문가 검증을 거쳐야 합니다.

## 창업 관점

Phase 3(트렌드) 단계인 만큼 시장과 진입 전략을 구체적으로 봅니다. LLM은 범용 기술이므로, 약사-창업자의 기회는 "더 좋은 LLM을 만드는 것"(빅테크의 영역)이 아니라 **특정 신약개발 워크플로에 LLM을 정밀하게 붙인 수직 도구**에 있습니다.

- **제품 아이디어(수직 SaaS)**: (1) 표적별 문헌·특허 근거를 자동 수집·요약해 근거표를 만드는 "타겟 도시에(dossier) 생성기", (2) 실험 노트·논문에서 반응 조건·활성값을 구조화 추출해 사내 데이터베이스로 넣는 파이프라인, (3) 규제 제출 문서(예: IND 모듈)의 초안을 근거와 함께 생성하는 어시스턴트.
- **시장·경쟁 구도**: 범용 LLM은 OpenAI·Anthropic·Google이 장악합니다. 그 위에 **Causaly, BenevolentAI**(문헌·지식그래프), **Elicit**(연구 자동화) 같은 응용 계층 플레이어가 있습니다. 빈 공간은 **"규제 번역 + 좁은 워크플로 + 출처 추적"**이 결합된 도구입니다.
- **기술적 해자(moat)**: 프롬프트나 범용 모델 접근성은 해자가 되지 못합니다. 해자는 ① 특정 워크플로에 맞춘 **자체 평가셋·검증 파이프라인**, ② **약학적 규제 판단**(무엇이 근거로 인정되는가, 어떤 출력이 허가 맥락에서 위험한가), ③ 고객 사용에서 쌓이는 피드백 데이터입니다. 순수 ML 팀은 ②를 흉내내기 가장 어렵습니다.
- **MVP 구상**: 바이브코딩으로 상용 LLM API + RAG(공개 논문·ChEMBL 근거)를 조합한 "단일 표적 근거 요약기"를 먼저 만들고, 소형 바이오텍·학계를 초기 고객으로 삼아 출력의 정확성 피드백을 수집하는 것이 현실적 시작점입니다. 정확성 검증 루프가 곧 제품의 신뢰이자 해자가 됩니다.

## 오늘의 과제

1. **(기초 학습)** temperature와 컨텍스트 창의 개념을 각각 3줄로 정리하고, "표적 문헌에서 활성값(IC50)을 정확히 추출하는 작업"에 어떤 값을 선택할지와 그 이유를 1문단으로 쓰세요.
2. **(비즈니스 분석)** LLM 응용 계층 회사 3곳(예: Causaly, Elicit, BenevolentAI)을 비교표로 정리하세요. 축: 대상 사용자, 핵심 기능, 근거·출처 제공 방식, 신약개발 특화 정도. 어디에 빈 공간이 있는지 한 문단으로 결론을 씁니다.
3. **(리서치 정리)** "LLM 환각(hallucination)이 신약개발에서 왜 특히 위험한가"를 주제로 1페이지를 작성하세요. 문헌 요약·규제 문서·물성 진술 중 하나의 시나리오를 골라, 환각이 초래할 구체적 피해와 이를 줄이는 설계(RAG·출처 강제·전문가 검수)를 약학적 관점에서 서술합니다.

- Singhal et al., "Towards Expert-Level Medical Question Answering with Large Language Models" (Med-PaLM 2 관련, 2023, 서지·수치 확인 필요) — 의료 도메인에서 LLM의 도달 수준 참고.
