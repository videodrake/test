# Day 4: RAG와 멀티모달 — 텍스트+분자+단백질 통합 AI

> 이전 학습에서 LLM 기초(Day 1), 화학 Foundation Model(Day 2), 스스로 도구를 부리는 AI 에이전트(Day 3)를 다뤘습니다. 지금까지의 모델은 대부분 **하나의 언어(텍스트 혹은 분자)** 안에서만 움직였습니다. 오늘은 두 가지 확장을 학습합니다. 하나는 모델이 자기 파라미터 밖의 **외부 지식을 실시간으로 검색해 근거로 삼는 RAG(검색 증강 생성)**, 다른 하나는 **텍스트·분자·단백질처럼 서로 다른 양식(modality)을 하나의 표현 공간에서 다루는 멀티모달 AI**입니다. 이 둘은 신약개발의 두 고질병 — LLM의 환각(hallucination)과 데이터 사일로(silo) — 을 정면으로 겨냥합니다.

## 개요

**RAG(Retrieval-Augmented Generation, 검색 증강 생성)**는 LLM이 답을 생성하기 전에 외부 지식 베이스(문헌, 특허, 자사 실험 데이터)에서 관련 문서를 **검색해 프롬프트에 끼워 넣고**, 그 근거 위에서 답을 만드는 구조입니다. 모델의 지식을 재학습 없이 최신·전용 데이터로 확장하고, **출처를 명시**해 환각을 억제하는 것이 핵심입니다. **멀티모달 AI(multimodal AI)**는 텍스트·분자 구조·단백질 서열·이미지처럼 형식이 다른 데이터를 **공통 임베딩 공간(shared embedding space)**에 정렬(align)해, "이 표현형(phenotype)을 유발하는 분자를 찾아라"처럼 양식을 넘나드는 질의를 가능하게 합니다. 신약개발 데이터는 본질적으로 멀티모달(논문 텍스트 + 화학 구조 + 오믹스 + 이미지)이므로, 이 둘을 결합하면 흩어진 지식을 하나의 추론 엔진으로 통합할 수 있습니다.

## 핵심 개념

### 1) RAG — 파라미터 밖의 기억을 붙이는 법

LLM의 지식은 학습 시점에 파라미터로 **고정**됩니다. 최신 논문도, 자사 내부 데이터도 모릅니다. RAG는 이 한계를 **검색(retrieval)**으로 우회합니다. 작동 순서는 **① 질문을 임베딩(embedding) 벡터로 변환 → ② 벡터 데이터베이스에서 의미가 가까운 문서를 검색 → ③ 검색된 문서를 프롬프트에 첨부 → ④ LLM이 그 근거로 답 생성**입니다.

핵심은 **의미 기반 검색(semantic search)**입니다. 키워드 일치가 아니라 **임베딩 벡터의 코사인 유사도(cosine similarity)**로 "뜻이 가까운" 문서를 찾습니다. 약학 연구자에게 이는 익숙한 발상입니다. 우리는 이미 **구조 유사성(structural similarity)이 활성 유사성으로 이어진다**는 SAR(구조-활성 관계) 원리를 알고 있습니다. RAG의 임베딩 검색은 **텍스트 공간에서의 유사성 검색**으로, "가까운 것은 비슷하다"는 동일한 직관을 벡터 공간에 옮긴 것입니다.

> 핵심: RAG는 **환각을 줄이고 출처를 추적 가능**하게 만듭니다. 규제 산업인 신약개발에서 "왜 이 결론에 도달했는가"의 근거 추적성(traceability)은 선택이 아니라 필수입니다. 근거 없는 그럴듯한 답보다, 출처가 붙은 검증 가능한 답이 훨씬 값집니다.

### 2) 청킹·임베딩·벡터DB — RAG의 3요소

RAG 품질은 다음 세 요소가 좌우합니다.

- **청킹(chunking)**: 긴 문서를 검색 단위로 쪼갭니다. 논문 한 편을 통째로 넣으면 노이즈가 많고, 너무 잘게 쪼개면 맥락이 끊깁니다. 도메인 구조(초록·방법·결과 단위)를 반영한 분할이 중요합니다.
- **임베딩 모델(embedding model)**: 텍스트를 벡터로 변환합니다. 일반 임베딩보다 **생의학 특화 임베딩**(예: PubMedBERT 계열)이 전문 용어를 더 정확히 포착합니다. 약학 문헌의 "clearance", "Cmax" 같은 용어가 일상 의미와 다르게 임베딩되어야 검색이 정확해집니다.
- **벡터 데이터베이스(vector database)**: 수백만 벡터에서 가까운 것을 빠르게 찾는 저장소(FAISS, Chroma, Qdrant 등). 근사 최근접 탐색(approximate nearest neighbor, ANN)으로 대규모에서도 실시간 검색을 지원합니다.

### 3) 멀티모달 정렬 — 다른 언어를 같은 공간에 겹치기

멀티모달 AI의 심장은 **대조 학습(contrastive learning)**입니다. 서로 짝이 맞는 데이터 쌍(예: 분자 구조 ↔ 그 분자를 설명하는 텍스트)을 **임베딩 공간에서 가깝게**, 짝이 아닌 쌍은 **멀게** 당기도록 학습합니다. 이미지-텍스트를 정렬한 CLIP(2021)이 원조이며, 신약개발에서는 **분자-텍스트, 단백질-텍스트** 정렬로 확장되었습니다.

정렬이 완성되면 **교차 양식 질의(cross-modal query)**가 가능해집니다. "혈액뇌장벽(blood-brain barrier)을 통과하는 소분자"라는 **텍스트로 분자를 검색**하거나, 반대로 낯선 분자 구조에 **자연어 설명을 생성**할 수 있습니다. 이는 약학 지식(어떤 물성 서술이 임상적으로 중요한가)을 **분자 검색의 질의어로 직접 활용**할 수 있다는 뜻입니다.

### 4) RAG × 멀티모달 × 에이전트의 결합

세 기술은 배타적이지 않고 **층으로 쌓입니다**. Day 3의 에이전트가 "무엇을 할지" 계획한다면, RAG는 각 단계에서 "근거를 어디서 가져올지"를, 멀티모달은 "어떤 양식이든 통합해 추론"하게 합니다. 즉 에이전트가 도구를 호출하되, 그 도구 중 하나가 **자사 문헌·실험 데이터를 검색하는 멀티모달 RAG**인 구조가 실무의 지향점입니다.

## 작동 원리와 아키텍처

바이브코딩으로 신약개발 지식 시스템을 만들 때 필요한 것은 임베딩 모델을 직접 학습시키는 능력이 아니라, **파이프라인 조립 구조**의 이해입니다.

```
[멀티모달 RAG 지식 시스템 아키텍처]
1. 데이터 수집: 논문(PDF)·특허·자사 assay 결과·분자 구조(SMILES)
2. 전처리·청킹: 문서 분할 + 분자/단백질은 별도 인코더로 임베딩
3. 인덱싱:
   - 텍스트 → 생의학 임베딩 → 벡터DB
   - 분자 → 화학 Foundation Model(Day 2) 임베딩 → 벡터DB
4. 질의 처리: 사용자 질문 → 임베딩 → 관련 텍스트+분자 동시 검색
5. 생성: 검색된 근거 + 질문 → LLM → 출처 명시 답변
6. 검증 계층: 출처 링크 제시 + 신뢰도/불확실성 표기
```

핵심 설계 결정을 정리합니다.

| 설계 결정 | 선택지 | 신약개발 맥락 추천 | 이유 |
|-----------|--------|-------------------|------|
| 임베딩 모델 | 범용 / 생의학 특화 | 생의학 특화 | 전문 용어 정확도 |
| 검색 방식 | 키워드 / 의미(벡터) / 하이브리드 | 하이브리드 | 정확한 용어 + 의미 포착 |
| 양식 통합 | 텍스트만 / 멀티모달 | 단계적 확장 | 텍스트 RAG로 시작, 분자 추가 |
| 근거 표기 | 없음 / 출처 링크 필수 | 출처 필수 | 규제·검증 요구 |

> 유의: RAG는 만능이 아닙니다. **검색이 틀리면 생성도 틀립니다(garbage in, garbage out)**. 관련 없는 문서가 검색되면 오히려 환각을 유도하고, 청킹이 나쁘면 맥락이 깨집니다. 검색 품질 평가(retrieval evaluation)를 별도로 두는 것이 필수이며, 멀티모달 정렬은 짝 데이터(pair data)가 부족하면 성능이 급락합니다.

## 신약개발 적용

RAG와 멀티모달은 이미 구체적 산출물을 냈습니다.

- **분자-텍스트 정렬 — MoleculeSTM**(Liu et al., *Nature Machine Intelligence*, 2023): 분자 구조와 텍스트 설명을 대조 학습으로 정렬해, **"용해도가 높은"** 같은 자연어 지시로 분자를 검색·편집(editing)하는 능력을 보였습니다. 약학적 물성 서술을 분자 설계의 질의어로 쓰는 대표 사례입니다. 앞서 **Text2Mol·MolT5**(Edwards et al., EMNLP 2021·2022)가 분자↔텍스트 번역의 토대를 놓았습니다.
- **단백질-텍스트 정렬 — ProtST**(Xu et al., *ICML*, 2023): 단백질 서열과 그 기능을 서술한 텍스트를 정렬해, 자연어로 단백질 기능을 검색·주석(annotation)하는 틀을 제시했습니다. 표적 이해를 텍스트 질의로 확장합니다.
- **과학 문헌 RAG — PaperQA**(Lála et al., 2023): 과학 논문을 검색·인용해 근거 기반으로 답하는 시스템으로, 생의학 질의응답에서 **출처를 명시**하는 RAG의 실효성을 보였습니다. 문헌 리뷰 자동화의 원형입니다.

| 항목 | 기존 방식 | RAG·멀티모달 기반 |
|------|----------|-------------------|
| 문헌 조사 | 연구자가 수동 검색·정독 | 질의 → 근거 인용 요약 자동 |
| 최신성 | 모델 학습 시점에 고정 | 벡터DB 갱신으로 실시간 반영 |
| 데이터 통합 | 텍스트·분자·오믹스 분리 | 공통 공간에서 교차 질의 |
| 환각 위험 | 근거 없는 생성 | 출처 추적으로 억제(완전 제거는 아님) |

> 유의: 위 모델들의 검색·생성 결과는 **가설 생성용**이며, 예측된 물성이나 문헌 요약을 임상적 확실성으로 받아들여선 안 됩니다. RAG가 출처를 붙여도 그 출처의 신뢰도·맥락은 사람이 판단해야 합니다.

## 창업 관점

Phase 3(트렌드) 단계인 만큼 시장과 진입 전략을 깊게 봅니다. RAG는 2024–2025년 엔터프라이즈 AI의 사실상 표준 패턴이 되었고, **범용 RAG 도구(LangChain, LlamaIndex 등)는 이미 상품화**되어 그 자체로는 해자가 아닙니다. 기회는 **도메인 데이터의 깊이와 검증 체계**에 있습니다.

- **제품 아이디어**: (1) 신약개발 특화 **문헌·특허 인텔리전스 플랫폼** — 표적·질환·화합물 질의에 출처를 붙여 답하는 근거 기반 리서치 어시스턴트, (2) 자사 실험 데이터(assay·ELN)와 공개 문헌을 통합하는 **사내 멀티모달 지식 베이스**, (3) "물성 서술 → 후보 분자 검색"의 **자연어 기반 분자 탐색 도구**(MoleculeSTM류 응용).
- **시장·경쟁 구도**: 상류의 범용 RAG 인프라는 빅테크와 프레임워크 생태계가 장악했습니다. 응용 계층에서는 **BenevolentAI**(문헌 기반 지식 그래프), **Causaly**(생의학 근거 검색), 일반 과학 문헌의 **Elicit·Consensus**가 인접합니다. 빈 공간은 **"자사 독점 데이터 + 약학적 검증이 결합된 수직 지식 시스템"**입니다.
- **기술적 해자(moat)**: 프레임워크가 아니라 ① **독점 데이터 자산**(자사 assay·실패 이력), ② **약학적 판단이 담긴 청킹·평가 기준**(어떤 근거가 임상적으로 유의미한가 — Day 1 ADMET 판단력과 연결), ③ **멀티모달 짝 데이터**(자사 분자-활성-문헌 연결)입니다. 특히 ②는 순수 소프트웨어 팀이 재현하기 어려운 약사-창업자의 핵심 경쟁력입니다.
- **MVP 구상**: 바이브코딩으로 공개 논문(PubMed 초록)을 벡터DB에 인덱싱하고, 생의학 임베딩 + LLM으로 "표적 X의 알려진 저해제와 근거 문헌"을 **출처와 함께** 요약하는 좁은 문헌 어시스턴트부터 시작하는 것이 현실적입니다. 이후 자사 데이터를 더하고 분자 검색(멀티모달)으로 확장하는 단계적 경로가 안전합니다.

## 오늘의 과제

1. **(기초 학습)** RAG 파이프라인의 4단계(임베딩 → 검색 → 첨부 → 생성)를 신약개발 질의 하나에 적용해 흐름을 직접 써보세요. 예: "표적 hERG의 알려진 저해제는?" 각 단계에서 무엇이 입력·출력되는지와, 검색이 잘못될 경우 어디서 오류가 생기는지 명시합니다.
2. **(비즈니스 분석)** 생의학·과학 문헌 검색 AI 3곳(예: Causaly, Elicit, Consensus)을 비교표로 정리하세요. 축: 대상 데이터(문헌/특허/자사), 출처 표기 방식, 대상 사용자, 멀티모달 지원 여부. 약사-창업자가 진입할 빈 공간을 한 문단으로 결론지으세요.
3. **(리서치 정리)** MoleculeSTM 또는 Text2Mol 논문의 초록을 읽고 "자연어로 분자를 검색·편집한다는 것의 신약개발적 의미"를 1페이지로 정리하세요. 약학적 물성 서술(예: "낮은 hERG 위험, 높은 BBB 투과")을 질의어로 쓸 때의 강점과, 짝 데이터 부족이라는 한계를 함께 논하세요.

## 참고 자료

- Liu et al., "Multi-modal molecule structure–text model for text-based retrieval and editing" (MoleculeSTM, *Nature Machine Intelligence*, 2023) — 분자 구조와 텍스트를 대조 학습으로 정렬해 자연어 기반 분자 검색·편집을 실현한 대표 사례.
- Edwards et al., "Translation between Molecules and Natural Language" (MolT5, *EMNLP*, 2022) 및 "Text2Mol" (*EMNLP*, 2021) — 분자↔텍스트 상호 번역의 토대를 놓은 연구.
