# Day 63: 분자 물성 예측 웹앱 만들기 (바이브코딩 실전)

> 이전 학습에서 바이브코딩의 분업 구조(Day 61)와 AI에게 도메인 규칙을 정확히 전달하는 프롬프트 엔지니어링(Day 62)을 다뤘습니다. 오늘은 이 둘을 합쳐 실제로 손에 잡히는 결과물 — **SMILES를 입력하면 분자 물성을 예측해 보여주는 웹앱** — 을 바이브코딩으로 설계하는 과정을 처음부터 끝까지 따라갑니다. 개념이 아니라 "무엇을, 어떤 순서로, AI에게 어떻게 시키는가"가 오늘의 주제입니다.

## 개요

**분자 물성 예측 웹앱**은 사용자가 화합물 구조(SMILES 문자열)를 입력하면, 분자량·logP·용해도·독성 플래그 같은 물성을 계산하거나 예측해 화면에 보여주는 최소 기능 제품(Minimum Viable Product, MVP)입니다. 이런 도구가 학습 목표인 이유는, AI 신약개발 스타트업의 거의 모든 초기 제품이 "구조를 넣으면 판단이 나오는 인터페이스"라는 동일한 골격을 공유하기 때문입니다. 오늘 만드는 앱은 나중에 ADMET 예측, 가상 스크리닝 대시보드, 논문 데이터 추출 도구로 확장될 **공통 뼈대**입니다. 바이브코딩의 진짜 가치는 여기서 드러납니다 — 창업자가 코드를 한 줄씩 짜지 않고도, 이 뼈대를 하루 안에 세우고 도메인 판단에 집중할 수 있습니다.

## 핵심 개념

물성 예측 웹앱은 크게 **계산 가능한 물성**과 **모델이 예측하는 물성**의 두 층으로 나뉩니다. 이 구분은 약학 전공자에게 익숙한 in silico 계산과 QSAR 예측의 차이 그대로입니다.

- **결정론적 계산 물성(descriptor)**: 분자 구조에서 규칙으로 바로 계산됩니다. **분자량(molecular weight)**, **logP**(지용성 지표), **수소결합 공여체/수용체 수**, **회전 가능 결합 수**, **위상학적 극성 표면적(Topological Polar Surface Area, TPSA)** 등입니다. 화학정보학 라이브러리 **RDKit**이 이 값들을 오차 없이 산출합니다. **리핀스키의 5원칙(Lipinski's Rule of Five)** — 분자량 500 이하, logP 5 이하, 공여체 5개 이하, 수용체 10개 이하 — 같은 경구 약물성 필터가 이 값들 위에서 바로 판정됩니다.
- **학습 기반 예측 물성**: **용해도(solubility)**, **pIC50**, **hERG 억제** 같은 값은 규칙으로 계산되지 않고, 데이터로 학습한 모델(Phase 2에서 다룬 QSAR·GNN)이 추정합니다. 이 값에는 항상 **불확실성**이 따르며, 사람이 그 신뢰도를 해석해야 합니다.

이 두 층을 섞지 않는 것이 설계의 핵심입니다. 계산 물성은 "참값"으로 표시해도 되지만, 예측 물성은 반드시 "추정치"임을 UI에 명시해야 합니다 — 이것이 예측 속성을 확실성으로 오독하지 않게 막는 규제·안전 관점의 기본 원칙입니다.

> **약학 지식이 UI 설계를 결정한다** — 어떤 물성을 상단에 크게 보여줄지, 어떤 값에 위험 색상을 입힐지는 순수 개발자가 판단할 수 없습니다. "TPSA 140 초과는 뇌혈관장벽(BBB) 투과 어려움", "hERG 위험은 빨강" 같은 표시 우선순위는 임상적 중요도에서 나오며, 이것이 곧 도구의 차별성이 됩니다.

## 작동 원리와 아키텍처

웹앱의 흐름은 **입력 → 검증 → 계산/예측 → 표시**의 4단계이며, 각 단계가 명확한 책임을 가진 모듈이 됩니다. 바이브코딩에서는 이 모듈 경계를 그대로 AI에게 지시하는 단위로 씁니다.

```
분자 물성 예측 웹앱 구성

1. 입력 모듈: 텍스트 입력창 (SMILES) 또는 구조 그리기 위젯
2. 검증 모듈: RDKit MolFromSmiles → 파싱 실패 시 오류 메시지
                (잘못된 입력을 조용히 통과시키지 않음)
3. 계산 모듈: RDKit Descriptors → MW, logP, HBD, HBA, TPSA, RotB
4. 규칙 판정: 리핀스키 5원칙 통과 여부 + 위험 플래그 색상 매핑
5. (선택) 예측 모듈: 사전학습 용해도/독성 모델 → 값 + 불확실성
6. 표시 모듈: 분자 2D 구조 그림 + 물성 카드 + 통과/경고 배지
```

기술 스택 선택은 초기 창업자의 속도를 좌우합니다. 아래는 "바이브코딩으로 하루 안에 세우기"를 기준으로 한 추천입니다.

| 설계 결정 | 선택지 | 초기 창업자 추천 | 이유 |
|-----------|--------|-----------------|------|
| 웹 프레임워크 | Streamlit / Gradio / Flask+React | **Streamlit** | 파이썬만으로 UI 완성, 배포 즉시 |
| 화학 처리 | RDKit / OpenBabel | **RDKit** | 표준·문서 풍부, AI가 코드 잘 생성 |
| 예측 모델 | 자체 학습 / 사전학습 로드 | **사전학습 로드** | MVP는 학습보다 통합 우선 |
| 배포 | 로컬 / Streamlit Cloud / HuggingFace Spaces | **HF Spaces** | 무료·공유 URL·데모 즉시 |
| 입력 검증 | 없음 / MolFromSmiles 필수 | **필수** | 쓰레기 입력=쓰레기 출력 방지 |

이 앱을 AI 에이전트에게 시킬 때의 프롬프트 골격은 Day 62의 원칙을 그대로 적용합니다 — 역할("RDKit·Streamlit에 익숙한 엔지니어로서"), 지시("위 6개 모듈로 SMILES 물성 앱을 작성하라"), 제약("파싱 실패는 사용자에게 명확히 알리고, 예측값은 '추정' 라벨을 붙일 것"), 형식("모듈별 함수로 분리, 실행 명령 포함"). 창업자의 일은 코드를 읽고 고치는 것이 아니라, **출력 앱이 도메인 규칙(단위·임계값·표시 우선순위)을 지켰는지 검증**하는 것입니다.

## 신약개발 적용

이 단순한 뼈대는 실제 산업 도구의 축소판입니다. **리핀스키 5원칙 필터**는 대형 제약사의 초기 라이브러리 스크리닝에서 수백만 화합물을 걸러내는 첫 관문으로 수십 년간 쓰여 왔고, RDKit 기반 물성 계산은 이 관문을 그대로 재현합니다. 여기에 사전학습 모델을 얹으면 예측 도구가 됩니다 — 예컨대 수용성 예측 벤치마크 데이터셋 **ESOL**(약 1,100개 화합물의 실측 용해도)로 학습한 모델을 붙이면, 구조만으로 대략적 용해도 추정치를 즉시 제공할 수 있습니다.

산업적으로도 "구조 입력 → 물성 판정" 인터페이스는 표준 형태입니다. 오픈소스 도구 **SwissADME**(무료 웹 도구)는 SMILES를 넣으면 약물성·ADME 지표를 표로 보여주는 대표 사례이며, 우리가 오늘 만드는 앱은 이 형태의 최소 복제본입니다. 차이는 커스터마이즈에 있습니다 — SwissADME가 일반 지표를 보여준다면, 창업자는 **자기 타겟·자기 안전성 기준에 맞춘 임계값과 플래그**를 넣어 특화된 판정 도구로 만들 수 있습니다. 바로 이 지점이 범용 도구와 도메인 특화 제품을 가르는 경계입니다.

## 창업 관점

물성 예측 웹앱은 그 자체로는 상품성이 낮습니다. 무료 도구(SwissADME 등)와 라이브러리(RDKit)가 이미 존재하기 때문입니다. 따라서 이 뼈대에서 **어디에 도메인 판단을 얹느냐**가 사업의 성패를 가릅니다. 세 가지 차별화 경로가 있습니다.

- **판정 규칙의 특화**: 범용 리핀스키가 아니라, 특정 질환·투여 경로(예: CNS 약물의 BBB 투과 기준, 흡입제의 입자·물성 기준)에 맞춘 판정 로직. 이 규칙은 약학 지식 없이는 채울 수 없어 복제 장벽이 됩니다.
- **워크플로 통합**: 단일 물성 조회가 아니라, ChEMBL·자체 실험 데이터와 연결된 **배치 스크리닝 + 우선순위 랭킹** 대시보드. 개별 계산은 무료여도, 파이프라인으로 엮인 판단은 유료 가치가 있습니다.
- **검증·신뢰 계층**: 예측값에 불확실성과 근거(유사 학습 화합물)를 함께 제시해, 규제·의사결정 맥락에서 신뢰할 수 있는 도구로 포지셔닝.

시장 관점에서, 이런 도구의 초기 고객은 대형 제약사가 아니라 **인실리코 역량이 부족한 소규모 바이오텍·CRO·학계 연구실**입니다. 이들은 자체 개발 인력이 없어 "구조를 넣으면 판단이 나오는" SaaS에 기꺼이 지불합니다. MVP 전략은 명확합니다 — 오늘 만든 뼈대에 자신의 전문 질환 영역 규칙 하나를 얹어 좁은 도구를 만들고(Day 61의 자본 효율 논리), 특정 사용자 집단에서 반복 사용 신호를 확인한 뒤 데이터·모델로 해자를 넓혀갑니다. 바이브코딩은 이 "좁게 시작해 빠르게 검증" 사이클의 속도를 결정적으로 높입니다.

## 오늘의 과제

1. **앱 명세서 작성 (50분)**: 본인의 관심 질환 영역을 하나 정하고, 오늘의 6개 모듈 구조에 맞춰 "이 앱이 무엇을 입력받아, 어떤 물성을 계산·예측하고, 어떤 기준으로 통과/경고를 표시할지"를 1페이지 명세서로 작성하세요. 특히 표시 우선순위(어떤 물성을 크게, 어떤 값에 위험 색상)를 임상적 근거와 함께 명시하세요 — 이것이 AI에게 넘길 spec입니다.

2. **기존 도구 해부 (40분)**: SwissADME 또는 유사 무료 물성 도구를 직접 사용해 임의의 SMILES 3개(예: 아스피린, 카페인, 관심 약물)를 넣어보고, (a) 어떤 물성을 보여주는지, (b) 무엇이 부족한지, (c) 내가 특화한다면 무엇을 추가/변경할지를 표로 정리하세요.

3. **검증 규칙 설계 (40분)**: 이 앱이 낼 수 있는 잘못된 출력 3가지(예: 유효하지 않은 SMILES를 통과시킴, logP 단위·부호 오류, 예측값을 참값처럼 표시)를 서술하고, 각각을 어느 모듈에서 어떤 규칙으로 막을지 Day 62의 "제약·검증" 프롬프트 문장으로 작성하세요.

## 참고 자료

- **RDKit 문서 (Descriptors·MolFromSmiles)**: rdkit.org — 분자 물성 계산과 SMILES 파싱의 표준 라이브러리. 오늘 앱의 계산·검증 모듈의 기반.
- **Lipinski et al., "Experimental and computational approaches to estimate solubility and permeability in drug discovery and development settings" (Adv. Drug Deliv. Rev., 1997)**: 리핀스키 5원칙의 원전(역사적 기준점) — 경구 약물성 필터의 근거.
- **SwissADME**: swissadme.ch — SMILES 입력 시 약물성·ADME 지표를 제공하는 무료 웹 도구. 우리가 만들 앱의 참조 형태이자 벤치마크.
- **Delaney, "ESOL: Estimating Aqueous Solubility Directly from Molecular Structure" (J. Chem. Inf. Comput. Sci., 2004)**: 용해도 예측 벤치마크의 표준 데이터셋 — 예측 모듈을 붙일 때의 출발점(확인 필요: 데이터 규모 약 1,100개).
