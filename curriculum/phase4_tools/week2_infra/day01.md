# Day 66: 데이터 파이프라인 — ChEMBL, PDB에서 모델 학습까지

> 이전 주(Week 1)에서는 바이브코딩으로 예측 웹앱과 API를 만들고 이를 MVP로 조립하는 법(Day 61~65)을 익혔습니다. 그 MVP의 예측 모델은 결국 **데이터**로 학습됩니다. 이번 주(Week 2)는 그 아래를 받치는 **데이터 인프라와 오픈소스 도구**를 다루며, 오늘은 그 출발점인 **원천 데이터베이스에서 모델 학습 데이터셋까지의 파이프라인**을 학습합니다.

## 개요

**데이터 파이프라인(data pipeline)**은 원천 데이터베이스(ChEMBL, PDB 등)에서 데이터를 추출해 정제·표준화·분할한 뒤 모델이 학습할 수 있는 형태로 변환하는 자동화된 흐름입니다. AI 신약개발에서 모델의 성능 상한은 알고리즘이 아니라 **데이터의 품질과 구성**이 결정하는 경우가 많습니다. 같은 GNN(그래프 신경망)이라도 중복 제거·활성값 단위 통일·누출(leakage) 없는 분할을 거친 데이터로 학습하면 성능과 신뢰도가 크게 달라집니다. 약학 전공자에게 이 단계는 특히 중요합니다 — 어떤 활성값이 임상적으로 의미 있는지, 어떤 실험 조건이 비교 가능한지를 판단하는 것이 바로 이 파이프라인의 핵심 의사결정이기 때문입니다.

## 핵심 개념

AI 신약개발의 주요 공개 데이터 원천과 그 성격을 먼저 구분합니다.

- **ChEMBL**: EMBL-EBI가 관리하는 생체활성(bioactivity) 데이터베이스. 화합물–표적–활성값(IC50, Ki, EC50 등)의 삼중 관계를 담고 있으며, 문헌에서 큐레이션된 정량적 활성 데이터가 핵심입니다. QSAR·물성 예측 모델의 표준 학습 소스입니다.
- **PDB(Protein Data Bank)**: 단백질·핵산의 실험적 3차원 구조 저장소. 도킹, 구조 기반 설계, 단백질–리간드 상호작용 학습의 원천입니다.
- **PubChem / BindingDB**: 각각 대규모 화합물·생리활성 데이터와 결합친화도(binding affinity) 특화 데이터. ChEMBL과 상호 보완적으로 쓰입니다.

이 데이터를 그대로 쓸 수 없는 이유는 약학 전공자가 가장 잘 압니다.

- **활성값의 이질성**: 같은 화합물–표적 쌍이라도 IC50는 실험 조건(효소 농도, 기질 농도)에 민감합니다. 서로 다른 논문의 값을 단순 병합하면 안 되며, 보통 **pChEMBL(=−log10(몰농도))** 같은 표준화된 로그 스케일로 통일합니다. 이는 약리학의 **pKi, pIC50** 표기와 동일한 사고입니다.
- **활성 단위·부호 혼재**: nM/µM 단위 혼용, `=`·`>`·`<` 관계 연산자(우측 검열, censored data) 처리 필요.
- **표적 정의의 모호성**: 단일 단백질인지 복합체·세포주인지에 따라 학습 의미가 달라집니다.

> 핵심: 데이터 정제의 판단 기준은 통계가 아니라 **약리학적 타당성**입니다. "이 두 측정값이 정말 비교 가능한가"라는 질문에 답할 수 있는 사람이 좋은 데이터셋을 만듭니다.

## 작동 원리와 아키텍처

파이프라인은 **추출(Extract) → 정제·표준화(Clean/Standardize) → 분할(Split) → 저장(Store)**의 흐름으로 설계합니다. Phase 4의 목표는 이 구조를 이해해 바이브코딩으로 AI에게 정확히 지시하는 것입니다.

```
데이터 파이프라인 구성:
1. 추출 모듈: ChEMBL SQLite/REST에서 표적 ID로 활성 데이터 쿼리
   → (화합물 SMILES, 표적, 활성값, 단위, 관계연산자) 테이블
2. 분자 표준화: RDKit로 염 제거·중성화·정규 SMILES(canonical) 생성, 중복 병합
3. 활성값 표준화: 단위 통일 → pChEMBL 계산, 검열 데이터 규칙 정의
4. 분할 모듈: scaffold split으로 train/valid/test 구성 (무작위 분할 금지)
5. 저장: Parquet/CSV + 데이터 버전·출처 메타데이터 기록
```

파이프라인 설계에서 가장 중요한 결정을 표로 정리합니다.

| 설계 결정 | 선택지 | 추천 | 이유 |
|-----------|--------|------|------|
| 데이터 분할 | random / scaffold / time | scaffold split | 유사 골격이 train·test에 동시 존재하는 누출 방지, 일반화 성능 정직하게 측정 |
| 활성값 표현 | 원값 / pChEMBL | pChEMBL(로그) | 스케일 정규화, 약리학 표준과 일치 |
| 중복 처리 | 삭제 / 중앙값 병합 | 중앙값 병합 | 실험 노이즈 완화하되 데이터 보존 |
| 검열 데이터(>,<) | 제거 / 유지 | 목적에 따라 | 분류엔 유용, 회귀엔 신중히 |

여기서 **scaffold split(스캐폴드 분할)**은 특히 중요합니다. 무작위 분할은 같은 화학 골격의 유사 분자가 학습·평가 세트에 섞여 들어가 성능을 과대평가하게 만듭니다. 이는 임상시험에서 **환자 무작위 배정 시 층화(stratification)**를 하지 않으면 결과가 왜곡되는 것과 같은 종류의 편향 통제 문제입니다.

## 신약개발 적용

데이터 파이프라인의 품질은 곧 모델의 신뢰도로 이어집니다.

- **Therapeutics Data Commons(TDC)**: 스탠퍼드 등이 주도한 프로젝트로, ADMET·상호작용·생성 등 신약개발 과제를 표준 데이터셋과 분할(scaffold split 포함)로 제공합니다. 파이프라인을 매번 새로 만들지 않고 벤치마크를 공유하게 만든 사례로, "데이터 표준화가 곧 인프라"임을 보여줍니다.
- **MoleculeNet 벤치마크**: 물성·독성 예측 모델을 비교할 때 무작위 분할과 scaffold 분할의 성능 차이가 크게 나는 것이 반복 보고되었으며, 이는 분할 전략이 결과 해석을 좌우함을 실증합니다.
- **ChEMBL의 규모**: ChEMBL은 수백만 건의 활성 측정과 200만 종 이상의 화합물을 담은 것으로 알려져 있으며(정확한 최신 릴리스 수치는 확인 필요), 이 원천에서 표적별로 수백~수천 건의 정제된 데이터를 뽑아 QSAR 모델을 만드는 것이 업계 표준 워크플로입니다.

기존 방식과의 차이는 명확합니다. 과거에는 연구자가 논문에서 활성값을 수기로 모아 스프레드시트를 만들었지만, 자동화된 파이프라인은 동일한 정제 규칙을 재현 가능하게 적용하고, 데이터 버전을 기록해 **모델 성능을 데이터 변경 이력과 연결**할 수 있게 합니다.

## 창업 관점

Phase 4답게 이 주제는 곧바로 제품·경쟁으로 연결됩니다.

- **제품 아이디어**: "정제된 학습용 데이터셋 + 파이프라인"을 상품화할 수 있습니다. 표적 이름만 입력하면 ChEMBL에서 정제·분할된 학습셋을 반환하는 SaaS, 또는 고객사 내부 실험 데이터와 공개 DB를 통합해 모델 학습 준비 상태로 만드는 데이터 인프라 서비스가 가능합니다.
- **기술적 해자(moat)**: 알고리즘은 오픈소스로 평준화되지만, **정제 규칙의 도메인 지식과 독점 데이터**는 복제하기 어렵습니다. 약학 전공자가 만든 "임상적으로 타당한 정제 규칙"은 그 자체로 차별화 자산입니다. 자사 wet lab 데이터를 공개 데이터와 결합한 하이브리드 데이터셋은 강력한 진입 장벽이 됩니다.
- **경쟁 구도**: TDC·MoleculeNet 같은 오픈 벤치마크가 무료로 존재하므로, 단순 데이터 제공만으로는 과금이 어렵습니다. 차별화는 "고객의 사적 데이터를 안전하게 통합·정제해 주는 워크플로"와 "규제 대응 가능한 데이터 계보(lineage) 관리"에서 나옵니다.

> MVP 구상: 특정 표적(예: hERG, CYP3A4) 하나에 대해 ChEMBL 정제 → scaffold 분할 → 학습 준비 완료 데이터셋을 자동 생성하는 파이프라인을 바이브코딩으로 만들고, 정제 규칙을 문서화해 "왜 이 값을 버렸는가"를 설명하는 리포트를 함께 제공하면, 데이터 신뢰성 자체가 판매 포인트가 됩니다.

## 오늘의 과제

1. **(리서치 정리)** ChEMBL 웹 인터페이스에서 익숙한 표적 하나(예: hERG 또는 EGFR)를 검색해, 조회되는 활성 데이터의 컬럼(활성 유형, 단위, 관계연산자)을 살펴보고 "이 데이터를 모델 학습에 쓰려면 어떤 정제가 필요한가"를 반 페이지로 정리하세요.
2. **(기초 학습)** scaffold split과 random split의 차이를 다룬 자료를 찾아, 왜 신약개발 모델 평가에서 scaffold split이 더 정직한 성능을 주는지 3줄로 요약하세요. 약학의 층화 무작위배정 개념과 연결해 설명해 보세요.
3. **(비즈니스 분석)** Therapeutics Data Commons(TDC)를 살펴보고, "공개 벤치마크가 무료인 상황에서 데이터 파이프라인으로 돈을 벌 수 있는 지점은 어디인가"를 3가지 가설로 정리하세요.
