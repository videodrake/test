# Day 72: UX/UI 설계 — 과학자를 위한 인터페이스

> 어제(Day 71)는 AI 신약개발 제품의 세 가지 비즈니스 유형과 네 가지 설계 패턴(인간 개입 루프·배치·대화형 워크벤치·API)을 다뤘습니다. 오늘은 그 패턴을 **실제로 과학자가 매일 열어 쓰는 화면**으로 번역하는 법, 즉 UX/UI 설계를 학습합니다. 좋은 모델이 실패하는 가장 흔한 이유는 정확도가 낮아서가 아니라, 과학자가 그 예측을 자기 의사결정에 끼워 넣을 수 없게 설계됐기 때문입니다.

## 개요

**UX(사용자 경험, User Experience)**는 사용자가 제품으로 목표를 달성하기까지의 전체 흐름을, **UI(사용자 인터페이스, User Interface)**는 그 흐름을 구성하는 구체적 화면·요소를 가리킵니다. AI 신약개발 제품의 사용자는 일반 소비자가 아니라 **의약화학자·약리학자·독성학자 같은 도메인 전문가**입니다. 이들은 이미 머릿속에 정교한 멘탈 모델(mental model)을 가지고 있어, 소비자 앱의 "단순함" 원칙을 그대로 적용하면 오히려 신뢰를 잃습니다. 오늘의 목표는 과학자용 인터페이스가 소비자용과 어떻게 다른지, 그리고 예측의 불확실성과 근거를 화면에 어떻게 녹여야 과학자가 실제로 그 예측을 쓰게 되는지를 설계 수준에서 이해하는 것입니다.

## 핵심 개념

과학자용 UX를 관통하는 세 가지 원리를 정의합니다.

- **정보 밀도(information density)**: 소비자 앱은 여백과 단순함을 추구하지만, 과학자는 한 화면에서 여러 물성을 동시에 비교하길 원합니다. SAR(구조-활성 관계, Structure-Activity Relationship) 테이블처럼 수십 개 분자 × 수십 개 컬럼을 한눈에 보는 **고밀도 그리드**가 오히려 전문가 생산성을 높입니다.
- **점진적 공개(progressive disclosure)**: 기본 화면은 핵심 결론(예: pIC50 예측값)만 보여주되, 클릭하면 근거(기여 원자, 유사 학습 데이터, 신뢰구간)가 단계적으로 열리는 구조입니다. 전문가는 "왜 이 값인가"를 따질 권리를 요구합니다.
- **신뢰 보정(trust calibration)**: 예측을 과신하지도, 불신하지도 않도록 **불확실성을 시각적으로 정직하게** 전달하는 것입니다. 점수 하나만 크게 띄우면 과신을, 경고를 남발하면 불신을 유발합니다.

약학 전공자에게 이 세 원리는 익숙한 판단의 연장입니다. 임상 데이터를 읽을 때 우리는 단일 평균값이 아니라 **신뢰구간(confidence interval)과 효과크기**를 함께 봅니다. ADMET 리포트에서 "logP 3.2"라는 숫자만으로 판단하지 않고, 그 값이 **허용 범위(예: Lipinski 규칙의 logP < 5) 안에 있는지**를 봅니다. 즉 약학 전공자는 "숫자를 임상적 임계값(threshold) 위에 올려놓고 해석하는" 훈련이 되어 있어, 어떤 정보를 전경에 두고 어떤 것을 배경에 둘지를 비약학 개발자보다 정확히 결정할 수 있습니다.

## 작동 원리와 아키텍처

과학자용 예측 인터페이스의 화면을 입력→처리→출력 흐름으로 분해합니다. Phase 4답게 "바이브코딩으로 이 화면을 AI에게 지시하려면 어떤 구조로 요청해야 하는가"의 수준으로 정리합니다.

```
예측 결과 카드(card)의 구성 요소:
1. 결론 레이어: 예측값 + 임계값 대비 색상(통과=초록/경계=노랑/위험=빨강)
2. 신뢰 레이어: 신뢰구간 막대 또는 "모델 적용 범위 밖" 경고(applicability domain)
3. 근거 레이어(펼침): 기여 원자 하이라이트 + 유사 학습 분자 top-3
4. 액션 레이어: "이 분자 저장 / 변형 제안 / 전문가 코멘트" 버튼
```

핵심 설계 결정을 표로 정리합니다.

| 설계 결정 | 선택지 | 추천 | 이유 |
|-----------|--------|------|------|
| 예측 표현 | 숫자만 / 숫자+색상코딩 | 숫자+임계값 색상 | 과학자가 통과/탈락을 즉시 판단 |
| 불확실성 | 숨김 / 신뢰구간 동반 | 신뢰구간 + 적용범위 경고 | 신뢰 보정, 규제 대응(Day 68 재현성) |
| 설명 방식 | 블랙박스 / 기여도 시각화 | 기여 원자 하이라이트 | 약학적 검증 가능(SAR 직관과 연결) |
| 레이아웃 | 단일 카드 / 비교 그리드 | 전환 가능한 그리드 | 리드 최적화의 다분자 비교 지원 |

> 설계 원칙: **과학자가 예측을 거부할 수 있게 하라.** 모델이 "적용 범위 밖(out of applicability domain)"임을 스스로 고백하는 화면은, 틀린 예측을 자신 있게 내놓는 화면보다 장기적으로 더 신뢰받습니다. 약학 전공자는 어떤 화학 공간이 학습 데이터에서 벗어나는지를 직관적으로 알기에, 이 경고의 임계선을 현실적으로 설정할 수 있습니다.

적용 범위(applicability domain)란 모델이 학습한 화학 공간의 경계를 뜻하며, 입력 분자가 이 경계 밖에 있으면 예측 신뢰도가 급락합니다. 이를 화면에 명시하는 것은 과학 소프트웨어 UX의 핵심 차별점입니다.

## 신약개발 적용

과학자용 인터페이스 설계가 실제 제품에서 어떻게 구현되는지 구체적 사례로 봅니다.

- **Schrödinger LiveDesign / Maestro**: 의약화학자가 분자를 그리거나 불러오면 FEP+ 결합 친화도 예측, 물성, docking 점수를 **고밀도 SAR 테이블**로 나란히 보여줍니다. 수십 개 후보를 행으로, 예측 물성을 열로 배치해 "다음에 합성할 분자"를 한 화면에서 고르게 하는 전형적 전문가 그리드입니다.
- **Benchling**: 2024년 기준 전 세계 수천 개 R&D 조직이 쓰는 생명과학 R&D 클라우드로, 전자 실험 노트(ELN)·분자 레지스트리·워크플로우를 하나의 UI로 통합했습니다. 개별 예측 정확도보다 **"과학자의 하루 전체를 담는 작업 환경"**을 장악해 교체 비용을 높인 사례입니다.
- **오픈소스 DataWarrior**: 화학 구조를 산점도·SAR 테이블로 대화형 탐색하게 해주는 무료 도구로, "분자를 점으로 찍고 클릭하면 구조가 뜨는" 상호작용이 과학자에게 얼마나 자연스러운지를 보여줍니다. 초기 창업자가 UX 레퍼런스로 삼기 좋은 사례입니다.

| 비교 축 | 소비자 앱 전형 | 과학자용 앱 전형 |
|---------|--------------|----------------|
| 정보 밀도 | 낮음(여백 중시) | 높음(비교 그리드) |
| 한 화면 의사결정 단위 | 1개 | 수십 개 분자 동시 |
| 불확실성 표시 | 대개 생략 | 필수(신뢰구간·적용범위) |
| 사용자 신뢰 기반 | 브랜드·단순함 | 근거 투명성·검증 가능성 |

## 창업 관점

Phase 4 후반답게 UX는 곧 사업 경쟁력입니다. 모델 정확도가 평준화되는 시대에 **UX가 해자(moat)의 상당 부분**을 차지합니다.

- **차별화 포인트는 "약학적 해석 레이어"**: 경쟁 제품이 pIC50 예측값을 숫자로 던질 때, 여러분은 "이 값이 임상적으로 무엇을 의미하는지"를 화면에 번역해 넣을 수 있습니다. 예컨대 hERG 예측 옆에 "이 수준의 차단은 QT 연장 위험 구간"이라는 규제·임상 맥락을 붙이는 것입니다. 이 해석 레이어는 비약학 경쟁자가 복제하기 가장 어려운 UI 자산입니다.
- **온보딩이 곧 유지율(retention)**: 과학자는 바쁘고 회의적입니다. 첫 5분 안에 "내가 아는 분자 하나를 넣어 예측이 상식과 맞는지" 확인시키는 온보딩 흐름이 전환율을 좌우합니다. 신뢰를 주는 첫 경험(sanity check) 설계가 핵심입니다.
- **MVP 구상**: 어제 설계한 대화형 워크벤치에, 오늘의 "결론→신뢰→근거→액션" 4레이어 예측 카드를 얹어 바이브코딩으로 구성해보세요. 핵심은 화면을 화려하게 만드는 것이 아니라, **과학자가 예측을 신뢰하거나 거부할 근거를 한 화면에서 제공**하는 것입니다. 저밀도 소비자 UI 템플릿을 그대로 쓰지 말고, SAR 그리드 같은 전문가 패턴을 우선 채택하세요.

## 오늘의 과제

1. **(리서치 정리)** Schrödinger LiveDesign, Benchling, DataWarrior 중 한 제품의 스크린샷이나 데모 영상을 찾아, 그 UI가 본문의 세 원리(정보 밀도·점진적 공개·신뢰 보정)를 각각 어떻게 구현했는지 반 페이지로 분석하세요. 잘된 점 2개, 아쉬운 점 1개를 지적하세요. 40분.
2. **(설계)** 여러분 MVP의 "예측 결과 카드"를 종이나 Figma로 스케치하세요. 결론·신뢰·근거·액션 4레이어가 모두 보여야 하며, 각 레이어에 "약학 지식이 개입하는 지점"을 최소 1곳 주석으로 표시하세요. 30분.
3. **(비즈니스 분석)** 소비자 앱 UX 원칙(단순함·여백)을 과학자용 제품에 그대로 적용하면 실패하는 이유를, 여러분이 아는 구체적 신약개발 작업(예: 리드 최적화 시 다분자 비교) 하나를 예로 들어 한 문단으로 설명하세요. 20분.
