# Day 73: 보안, 데이터 프라이버시, 규제 준수

> 어제(Day 72)는 과학자가 예측을 신뢰하고 의사결정에 끼워 넣도록 만드는 UX/UI 설계를 다뤘습니다. 그런데 과학자가 그 화면에 입력하는 데이터는 대부분 **회사의 핵심 자산(미공개 화합물 구조)이거나 규제 대상(환자·임상 데이터)**입니다. 오늘은 AI 신약개발 제품이 반드시 갖춰야 할 보안·데이터 프라이버시·규제 준수를, 아키텍처 설계 수준에서 학습합니다. 기능이 아무리 좋아도 이 요건을 통과하지 못하면 제약사는 제품을 도입하지 않습니다.

## 개요

AI 신약개발 제품이 다루는 데이터는 두 종류의 특수성을 동시에 가집니다. 첫째, 미공개 화합물 구조·활성 데이터는 **기업 지식재산(IP)의 핵심**이어서 유출 시 특허 전략 전체가 무너집니다. 둘째, 임상·유전체·환자 데이터는 **법적 보호 대상(GDPR, HIPAA 등)**이자 **규제 감사 대상(FDA 21 CFR Part 11)**입니다. 따라서 보안은 사후에 덧붙이는 기능이 아니라 제품 아키텍처의 제1 제약조건입니다. 오늘의 목표는 어떤 요건이 존재하고(Part 11, GxP, GDPR), 그것을 어떻게 시스템 설계로 번역하며, 데이터를 공유하지 않고도 학습하는 기술(연합학습)이 왜 이 산업의 핵심 경쟁력이 되는지를 이해하는 것입니다.

## 핵심 개념

규제 대상 소프트웨어가 충족해야 할 핵심 용어를 정의합니다.

- **데이터 무결성(data integrity)과 ALCOA+ 원칙**: 규제 데이터는 **Attributable(귀속 가능)·Legible(판독 가능)·Contemporaneous(동시 기록)·Original(원본)·Accurate(정확)** 하고, 여기에 Complete·Consistent·Enduring·Available을 더한 조건을 만족해야 합니다. 약학 전공자에게 이는 **임상시험 자료(CRF)·GLP 독성시험 기록 관리에서 이미 훈련된 원칙**입니다.
- **감사 추적(audit trail)**: 누가·언제·무엇을·왜 바꿨는지 모든 변경을 되돌릴 수 없게(tamper-evident) 기록하는 것입니다. **FDA 21 CFR Part 11**(1997년 제정, 전자기록·전자서명 규정)의 핵심 요구사항입니다.
- **GxP와 컴퓨터 시스템 검증(Computer System Validation, CSV)**: GLP/GCP/GMP 등 규제 영역에서 쓰이는 소프트웨어는 "의도대로 작동함"을 문서로 입증해야 하며, **GAMP 5**가 그 업계 표준 프레임워크입니다.
- **프라이버시 보호 기계학습(privacy-preserving ML)**: 데이터를 한곳에 모으지 않고 학습하는 기술군입니다. **연합학습(federated learning)**, 차분 프라이버시(differential privacy), 암호화 연산(homomorphic encryption) 등이 포함됩니다.

약학 전공자의 우위는 분명합니다. 비약학 개발자는 "감사 추적"을 단순 로그로 이해하지만, 여러분은 **GLP 실험 노트의 서명·날짜·수정 규칙**이 왜 그렇게 엄격한지, 규제 감사관이 실제로 무엇을 보는지를 압니다. 즉 Part 11 요건을 "어느 수준까지" 구현해야 충분한지 판단할 수 있습니다.

## 작동 원리와 아키텍처

규제 준수형 제품의 보안 아키텍처는 계층으로 설계합니다. 입력(사용자·데이터) → 처리(격리·암호화·기록) → 출력(검증 가능한 결과)의 흐름입니다.

```
[규제 준수형 SaaS 아키텍처 계층]
1. 접근 제어: RBAC(역할 기반 권한) + MFA + SSO 연동
2. 전송/저장 암호화: TLS 1.2+ (전송), AES-256 (저장)
3. 테넌트 격리: 제약사별 데이터 논리적/물리적 분리 (크로스 테넌트 유출 차단)
4. 감사 로그: 모든 CRUD·예측 요청을 불변 저장소에 기록 (Part 11)
5. 전자서명 모듈: 결과 승인 시 서명자·시점·의미 기록
6. 검증 문서: IQ/OQ/PQ 테스트 산출물 (CSV/GAMP 5)
```

핵심 설계 결정을 표로 정리합니다.

| 설계 결정 | 선택지 | 제약사 환경 추천 | 이유 |
|-----------|--------|-----------------|------|
| 배포 모델 | 퍼블릭 클라우드 / VPC 전용 / 온프레미스 | VPC 전용 또는 온프레미스 | 미공개 구조 유출 우려로 보안팀 승인 용이 |
| 데이터 학습 | 중앙 집중 / 연합학습 | 연합학습 | 원본 데이터 외부 반출 없이 모델 개선 |
| 감사 로그 | 수정 가능 DB / 추가 전용(append-only) | 추가 전용 | 변조 불가성 입증 (ALCOA의 Original·Enduring) |

연합학습의 작동 원리는 간단합니다. 각 제약사 서버에서 **로컬 데이터로 모델을 학습**하고, 원본 데이터 대신 **모델의 가중치 업데이트(gradient)만** 중앙에 보냅니다. 중앙은 이를 평균하여 전체 모델을 개선한 뒤 다시 배포합니다. 데이터는 한 번도 회사 밖으로 나가지 않습니다.

## 신약개발 적용

가장 상징적 사례는 **MELLODDY 프로젝트(2019~2022)**입니다. Amgen·AstraZeneca·Bayer·Novartis 등 **10개 글로벌 제약사**가 참여해, 약 **2,100만 개 분자**의 데이터를 **서로 공개하지 않고** 연합학습으로 공동 물성 예측 모델을 학습했습니다. 경쟁사끼리 가장 민감한 화합물 라이브러리를 합치되 원본은 지키는 구조로, "데이터 프라이버시가 곧 협업의 전제"임을 입증한 사례입니다(세부 성능 수치는 공개 자료 확인 필요).

규제 측면에서는 **FDA 21 CFR Part 11**이 모든 전자기록 시스템의 기준선입니다. 임상·GLP 데이터를 다루는 소프트웨어는 감사 추적·전자서명·접근 통제를 갖춰야 하며, 이를 충족하지 못하면 규제 제출용 데이터 생성에 쓸 수 없습니다. 유럽에서는 **GDPR**이 유전체·환자 데이터 처리를 통제하여, 환자 데이터를 쓰는 제품은 가명화·동의 관리가 필수입니다.

| 구분 | 비규제 SaaS | AI 신약개발 SaaS |
|------|------------|-----------------|
| 데이터 민감도 | 일반 | IP + 규제 대상 이중 민감 |
| 감사 요구 | 선택적 | Part 11 필수 |
| 배포 유연성 | 클라우드 기본 | VPC/온프레미스 요구 빈번 |

## 창업 관점

Phase 4 후반답게 보안·규제는 비용이 아니라 **진입 장벽이자 해자(moat)**입니다. 모델 정확도가 평준화될수록, "제약사 보안팀과 규제팀의 승인을 통과할 수 있는가"가 계약 성사의 실제 병목이 됩니다.

- **컴플라이언스는 세일즈 자산**: SOC 2 Type II, ISO 27001 인증과 Part 11 대응 체크리스트는 엔터프라이즈 영업에서 수개월의 보안 심사를 단축시킵니다. 초기 스타트업일수록 이 문서를 먼저 준비하면 대형 고객의 "벤더 보안 평가(vendor security assessment)"를 통과하기 쉽습니다.
- **배포 모델이 BM을 좌우**: 보안 민감 고객에게는 **VPC 전용·온프레미스 티어**를 프리미엄 가격으로 제공하는 것이 유효한 비즈니스 모델입니다. 데이터가 회사 밖으로 안 나간다는 보장이 가격 프리미엄을 정당화합니다.
- **약학적 해자**: 경쟁사가 "Part 11 지원"을 체크박스로 넣을 때, 여러분은 **규제 감사관의 관점에서 무엇이 실제로 필요한지**를 알아 과잉·과소 구현을 피할 수 있습니다. GLP/GCP 데이터 흐름을 이해한 창업자만이 "어느 데이터에 어느 수준의 무결성 통제가 필요한지"를 정확히 설계합니다.
- **MVP 구상**: 어제의 예측 워크벤치에 **(1) 추가 전용 감사 로그, (2) 역할 기반 접근 제어, (3) 결과 승인 전자서명** 세 가지만 바이브코딩으로 얹으세요. 화려한 기능보다 이 세 가지가 제약사 파일럿 계약의 통과 조건인 경우가 많습니다.

## 오늘의 과제

1. **(리서치 정리)** MELLODDY 프로젝트를 검색해, "경쟁 제약사들이 데이터를 공개하지 않고 어떻게 공동 모델을 만들었는지"를 연합학습 작동 원리와 함께 반 페이지로 정리하세요. 이 구조가 왜 신약개발에서 특히 가치 있는지 한 문단으로 덧붙이세요. 40분.
2. **(설계)** 여러분 MVP의 데이터 흐름도를 그리고, 사용자가 미공개 구조를 입력하는 지점부터 예측 결과가 저장되는 지점까지 **암호화·접근제어·감사로그가 각각 어디에 들어가야 하는지**를 표시하세요. ALCOA+ 중 하나 이상이 어떻게 충족되는지 주석을 다세요. 40분.
3. **(비즈니스 분석)** "우리 제품은 온프레미스로도 배포 가능하다"는 메시지가 제약사 영업에서 왜 가격 프리미엄과 전환율을 동시에 높이는지, 보안팀·규제팀 각각의 관점에서 한 문단씩 설명하세요. 20분.

## 참고 자료

- **컨소시엄/사례**: MELLODDY (Machine Learning Ledger Orchestration for Drug Discovery, 2019~2022) — 10개 제약사가 연합학습으로 공동 물성 예측 모델을 구축한 대표 사례. IMI(Innovative Medicines Initiative) 지원 프로젝트.
- **규제 문서**: FDA, *21 CFR Part 11: Electronic Records; Electronic Signatures* (1997) — 전자기록·전자서명의 감사 추적·접근 통제 요건을 규정한 기준 문서.
- **업계 표준**: ISPE GAMP 5 (*A Risk-Based Approach to Compliant GxP Computerized Systems*, 2nd ed.) — 규제 환경 소프트웨어의 컴퓨터 시스템 검증(CSV) 프레임워크.
- **개념/프레임**: 데이터 무결성 ALCOA+ 원칙 — 임상·GLP 데이터 관리의 핵심으로, 약학 전공자가 규제 준수형 제품 설계에서 직접 활용 가능.
