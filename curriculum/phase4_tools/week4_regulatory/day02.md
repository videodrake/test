# Day 77: AI 모델의 규제 제출 — 검증, 문서화, 투명성

> 이전 학습(Day 76)에서 FDA·EMA·MFDS의 AI 규제 **원칙**과 FDA의 7단계 신뢰성 평가 프레임워크를 다뤘습니다. 오늘은 그 프레임워크를 실제 **제출 자료로 구현**하는 방법을 학습합니다. 즉 "어떤 증거를, 어떤 형식으로, 얼마나 투명하게 제출해야 규제 당국이 모델을 신뢰하는가"라는 실무 질문에 답합니다.

## 개요

규제 제출(regulatory submission)이란 AI 모델의 신뢰성을 뒷받침하는 증거를 당국이 심사할 수 있는 형태로 정리해 제출하는 활동입니다. Day 76의 7단계 프레임워크가 "무엇을 해야 하는가"의 원칙이라면, 오늘의 주제는 "그 결과를 어떤 문서로 남기는가"의 실행입니다. 핵심은 세 가지로 압축됩니다. **검증(validation)** — 모델이 사용 맥락에서 작동함을 입증하는 증거, **문서화(documentation)** — 그 증거를 추적 가능하게 기록하는 체계, **투명성(transparency)** — 심사자가 모델의 한계와 작동을 이해할 수 있게 하는 설명입니다. 이 세 축은 약학 전공자가 임상시험 자료 작성에서 이미 익숙한 "프로토콜 → 실행 → 보고서" 구조와 동일한 논리를 따릅니다.

## 핵심 개념

**1. 검증(validation)과 신뢰성 증거(credibility evidence)**

규제 맥락의 검증은 Day 74에서 배운 소프트웨어 테스팅보다 넓은 개념입니다. 단순히 "코드가 작동하는가"가 아니라, **"이 모델의 출력을 특정 규제 결정의 근거로 삼아도 되는가"** 를 입증합니다. FDA 초안 가이드라인은 이를 **신뢰성 증거**로 부르며, 위험 등급(영향력 × 중대성)이 높을수록 더 강한 증거를 요구합니다. 증거는 ① 데이터 적합성(관련성·신뢰성), ② 성능(정확도·민감도·특이도 등 사용 맥락에 맞는 지표), ③ 견고성(robustness, 입력 변동에 대한 안정성), ④ 적용 범위(applicability domain, 모델이 신뢰 가능한 입력 공간)의 네 축으로 구성됩니다. 약학적으로 이는 분석법 밸리데이션(analytical method validation)의 정확성·정밀성·특이성·범위 개념과 구조적으로 대응합니다.

**2. 우수 머신러닝 규범(Good Machine Learning Practice, GMLP)**

FDA·Health Canada·영국 MHRA는 2021년 **GMLP 10대 지도 원칙**을 공동 발표했고, 2024년에는 이를 보완하는 **투명성 원칙**을 추가로 내놓았습니다. 핵심은 전주기(데이터 수집 → 학습 → 배포 → 모니터링)에 걸쳐 품질을 내장하라는 것으로, 특히 "학습·시험 데이터의 독립성 보장", "임상적으로 의미 있는 성능 지표 선택", "배포 후 모니터링"을 강조합니다. 이는 의료기기 트랙에서 출발했지만 의약품 개발 AI에도 사실상의 모범 관행(best practice)으로 참조됩니다.

**3. 사전 결정 변경 관리 계획(Predetermined Change Control Plan, PCCP)**

AI 모델은 재학습으로 계속 변합니다. PCCP는 "어떤 변경을, 어떤 범위에서, 어떻게 검증하며 허용할지"를 **미리 규제 당국과 합의**해 두는 장치입니다. 다만 주의가 필요합니다. PCCP는 2022년 FDORA 법에 근거해 **의료기기(CDRH) 트랙에만 공식 경로로 존재**하며, 의약품·바이오(CDER) 쪽에는 아직 동일하게 명문화된 경로가 없습니다(확인 필요). 의약품 AI에서는 "계획된 재평가·데이터 드리프트 모니터링"이라는 개념 수준으로만 반영되고 있습니다.

## 작동 원리와 아키텍처

제출 자료는 하나의 **문서화 번들(documentation bundle)** 로 설계하면 명확합니다. 제품을 만들 때 예측 결과만이 아니라, 그 예측을 뒷받침하는 메타데이터를 처음부터 함께 생성하도록 아키텍처를 짜야 합니다.

```
규제 제출용 문서화 번들 (모델 1개당)
1. 모델 카드      : 용도, 사용 맥락(COU), 위험 등급, 학습 데이터 출처
2. 데이터 시트    : 데이터 계보(provenance), 라벨 정의, 대표성·편향 분석
3. 검증 보고서    : 성능 지표 + 적용 범위 + 견고성 시험 결과
4. 감사 추적 로그 : 버전·하이퍼파라미터·학습 데이터 해시(재현 가능성)
5. 투명성 문서    : 한계, 실패 모드, 설명(XAI) 결과, 인간 감독 지점
```

| 설계 결정 | 선택지 | 추천 | 이유 |
|-----------|--------|------|------|
| 문서 생성 시점 | 사후 작성 / 자동 생성 | 자동 생성 | 추적성·재현성 확보, 누락 방지 |
| 설명 방법 | 전역(global) / 국소(local) | 둘 다 | 규제는 개별 예측의 근거(local)도 요구 |
| 버전 관리 | 모델만 / 모델+데이터+코드 | 전부 | 재현성은 셋이 묶여야 성립 |

> 투명성은 "모델을 전부 공개하라"가 아닙니다. 심사자가 **한계와 적용 범위를 이해**하도록 돕는 것이 핵심입니다. 설명가능 AI(Explainable AI, XAI) — 예: SHAP 값, attention 가중치 — 는 개별 예측이 어떤 입력 특성에 근거했는지 보여주는 수단이며, 이는 Day 74의 재현성 개념이 "타인이 이해 가능한 형태"로 확장된 것입니다.

## 신약개발 적용

검증·문서화·투명성이 실제로 요구 강도를 바꾸는 지점은 **사용 맥락**입니다. 예를 들어 전임상 독성시험에서 hERG 억제(Day 74에서 다룬 심장 안전성 지표)를 AI로 예측하고 그 결과를 규제 제출 자료에 포함한다면, 심사자는 단순 정확도가 아니라 "이 모델의 적용 범위 안에 해당 화합물이 들어오는가", "음성 예측의 신뢰도는 어떻게 입증되는가"를 묻습니다. 모델 카드에 학습 데이터의 화학 공간을 명시하고, 대상 화합물이 그 범위를 벗어나면 신뢰도를 낮춰 보고하는 설계가 그래서 필요합니다.

산업 현황도 이 방향으로 수렴합니다. FDA 초안 가이드라인은 2025년 4월 7일 의견 수렴을 마쳤고, 최종본은 2026년 2분기 발간이 예상된다고 보도되었습니다(확인 필요). FDA·EMA가 공동 발표한 AI 원칙은 "계획된 모니터링과 데이터 드리프트 감시"를 포함해, 제출이 일회성 심사가 아니라 **전주기 관리**임을 분명히 합니다.

| 구분 | 성능 중심 모델 | 제출 가능 모델 |
|------|----------------|----------------|
| 산출물 | 예측값 | 예측값 + 신뢰성 증거 번들 |
| 성능 지표 | 전체 정확도 | 사용 맥락별 지표 + 적용 범위 |
| 변경 관리 | 자유 재학습 | 재평가·드리프트 모니터링 계획 |

## 창업 관점

Phase 4의 실무 주간답게, 문서화와 투명성은 **제품화 가능한 레이어**입니다. 대부분의 AI 신약개발 도구는 예측 성능에만 집중하고, 그 예측을 "규제에 낼 수 있는 증거"로 포장하는 작업은 여전히 수작업·외주 컨설팅에 의존합니다.

- **제품 아이디어**: 예측 파이프라인에 모델 카드·데이터 시트·검증 보고서·감사 추적을 **자동 생성**하는 "규제 문서화 자동화(documentation-as-code)" 레이어. 연구자가 모델을 돌리면 제출 초안 패키지가 함께 나옵니다.
- **시장·경쟁**: 순수 모델 성능은 레드오션이지만, GMLP·FDA 7단계를 템플릿으로 내장한 문서화 도구는 공백이 큽니다. 컨설팅 외주 비용을 소프트웨어 구독으로 전환하는 고전적 기회입니다.
- **약학적 해자**: "임상적으로 의미 있는 성능 지표 선택"과 "적용 범위의 임상적 타당성 판단"은 약리·규제 지식 없이는 설계할 수 없습니다. 비전공자가 만든 문서화 도구는 형식만 채우고 내용의 타당성을 검증하지 못합니다.
- **MVP 구상**: Day 75 로드맵의 단일 물성 예측 도구에, 예측마다 모델 카드와 적용 범위 플래그를 자동 첨부하는 기능을 바이브코딩으로 붙여 "제출 가능한 출력"을 첫 차별점으로 삼으세요.

## 오늘의 과제

1. **(설계 과제)** 여러분이 Phase 2~4에서 구상한 모델 하나(예: 용해도 또는 hERG 예측)의 **모델 카드 초안**을 작성하세요. 용도·사용 맥락·위험 등급·학습 데이터 출처·적용 범위·알려진 한계의 6개 항목을 각 2~3문장으로 채웁니다. 50분.
2. **(비교 분석)** GMLP 10대 지도 원칙(2021)을 찾아 읽고, 그중 "데이터 독립성", "임상적으로 의미 있는 성능 지표", "배포 후 모니터링" 3개 원칙이 여러분 모델의 검증 계획에 각각 어떤 구체적 활동을 추가로 요구하는지 표로 정리하세요. 40분.
3. **(비즈니스 분석)** "규제 문서화 자동화" 제품이 바이오텍 고객의 시간·비용을 어디서 절감하는지 3가지로 정리하고, 수작업 컨설팅 대비 구독형 소프트웨어가 정당화할 수 있는 가격 포지션을 반 페이지로 논증하세요. 30분.

## 참고 자료

- **FDA 초안 가이드라인**: U.S. FDA, *Considerations for the Use of Artificial Intelligence to Support Regulatory Decision-Making for Drug and Biological Products* (2025년 1월 초안, 의견 수렴 2025년 4월 7일 마감) — 사용 맥락 기반 신뢰성 증거의 문서화 기대치를 규정. 최종본(2026년 2분기 예상) 발간 여부는 FDA 가이드라인 페이지에서 확인 권장.
- **GMLP 지도 원칙**: U.S. FDA · Health Canada · UK MHRA, *Good Machine Learning Practice for Medical Device Development: Guiding Principles* (2021, 2024년 투명성 원칙 추가) — 전주기 품질·투명성의 국제 공통 기준. 의료기기 트랙 문서이나 의약품 AI에도 모범 관행으로 참조됨.
- **모델 카드 개념**: Mitchell et al., *Model Cards for Model Reporting* (2019) — 모델의 용도·성능·한계를 표준 양식으로 문서화하는 방법론. 규제 문서화의 사실상 출발점.
